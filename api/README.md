# API — optional, not deployed

An Express wrapper around `js/passwordgenerator.js`, exposing `GET /generate`.

**It is not running anywhere.** `api-passwordgenerator.clicface.com` was
decommissioned: nothing used it, the page never called it, and it had been
answering 502 for some time before it was retired.

## Think before hosting it

The page it belongs to tells visitors:

> All random passwords generated by this software are available on your local
> computer only. No passwords are transferred over the Internet.

That is true because generation happens in the browser. An HTTP endpoint is
the opposite trade: the password is produced on a server, travels over the
wire, and passes through whatever proxies and logs sit in between. For a
password generator that is a weaker position than doing nothing at all.

If you host it anyway, it is in reasonable shape — bounded input, rate
limiting, no stack traces in error bodies — and `npm test` covers all of it.
But prefer the browser unless a caller genuinely cannot generate locally.

## Running it

```sh
npm install
npm start          # PORT=3000 by default, override with .env or the environment
npm test           # boots the server and exercises /generate
```

## `GET /generate`

| Parameter | Type | Default | Notes |
| --- | --- | --- | --- |
| `length` | integer | `8` | Must be 3–120. Omit for the default; anything else is a `400`. |
| `AlphaLower` | boolean | `true` | `abcdefghjkmnpqrstuvwxyz` |
| `AlphaUpper` | boolean | `true` | `ABCDEFGHJKLMNPQRSTUVWXYZ` |
| `Num` | boolean | `true` | `23456789` |
| `HypenDashUnderscore` | boolean | `false` | `-_` — the spelling is the wire format |
| `Special` | boolean | `false` | `~!@#$%^&*()=+[]{};:,.<>/?` |
| `Ambiguous` | boolean | `false` | Adds `i o l I O 0 1` back to the pool |

Booleans are asymmetric: those defaulting to `true` are disabled only by the
literal `false`, those defaulting to `false` are enabled only by the literal
`true`.

Answers `200 {password, score}`, `400 {error}` for impossible requests, and
`429 {error}` with `Retry-After` past 60 requests per minute per IP
(`RATE_LIMIT_MAX`, `RATE_LIMIT_WINDOW_MS`).

Behind a reverse proxy set `TRUST_PROXY`, or every visitor is rate-limited as
one — but setting it carelessly lets a client forge `X-Forwarded-For` and
dodge the limit entirely.
